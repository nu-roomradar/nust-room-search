# RoomRadar に参加する人へ（最初の1日）

運営の「いつ・何を・壊れたら」は [`OPERATIONS.md`](OPERATIONS.md)、守るルールは [`../CLAUDE.md`](../CLAUDE.md)。
ここには **コードのどこに何があるか** と **最初にやってみること** だけを書く。

最終更新: 2026-09-23

## 1. まず知っておくこと（3つ）

1. **テスト運用中の非公式サービス。** 学生課・教務課と協議中。画面の「テスト運用中・非公式」表記は消さない（hook が機械的に止める）。
2. **「予約」と言い切らない。** アプリの仮予約は他の学生への目安の共有で、教室の使用権は保証しない。
3. **作業は Claude Code on the web（iPad 可）で行い、`main` に push すると本番に出る。** テストは GitHub Actions（`ci.yml`）が push のたびに回す。

## 3. 空き判定のしくみ（ここだけは理解しておく）

- 「空き」＝ **教室マスタにある教室** のうち、選んだ年度・学期・曜日・時限の **時間割に授業が1つも入っていない** もの。
- 教室マスタは理工学部・大学院の時間割から作る。短期大学部の授業は「埋まっている」判定にだけ使う（短大専用教室は検索結果に出さない）。
- **隔週の授業は毎週あるものとして扱う**（今週が授業週か分からないため）。隔週の授業1つだけの教室は、結果の下の「週によっては空き」に別枠で出る。
- 時間割に無い補講・ゲリラ授業は分からない。だから画面で「ドア越しに確認」をお願いしている。利用者の「実は使われていた」報告が2件たまると「使用中の可能性」になる。
- 仮予約・報告は Render の上の SQLite。再デプロイで消える（`DATA_DIR` を永続ディスクに向ければ残る。OPERATIONS 6.）。

## 4. 最初にやってみること

Claude Code on the web でこのリポジトリを開き、Claude に次を順に頼んでみる。

1. 「テストを全部回して」— 全部 OK になることを確認する
2. 「アプリをローカルで起動して、スマホ幅でスクショを見せて」（`/verify-ui`）— 画面と表記の確認のしかたが分かる
3. 「2026年度後期の月曜3限に空いている駿河台校舎の教室は？」— 検索ロジックを Claude に説明させる
4. 「`docs/OPERATIONS.md` の `[要記入]` を一緒に埋めたい」— 引き継ぎの残りを確認する

## 5. 変更するときの型

1. 変更を頼む → 2. Claude がテストを回す → 3. 画面の変更なら `/verify-ui` でスクショを目で見る → 4. commit & push（毎回確認が出る） → 5. 数分後に本番 URL を自分のスマホで開いて確かめる（この環境からは本番 URL が見えない）

時間割・空き判定の意味が変わる変更（短大の扱い、隔週の扱いなど）は、ひとりで決めずに運営で相談する。
