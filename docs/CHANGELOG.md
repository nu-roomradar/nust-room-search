# RoomRadar 更新履歴（CHANGELOG）

運営チームの記録です。利用者が触れるサービス（検索アプリ・紹介ページ・このサービスについて・時間割データ）の版を、新しい順に並べています。
**画面・紹介ページ・Instagram などの公開の履歴に写すときは、`docs/OPERATIONS.md` 4.11 の「更新のたびの手順」6 の決まりで書き直してください。**

## 番号の決め方（要約）

- 形は **vX.Y.Z** です。上げた数字より右は0に戻します。
  - X＝節目
  - Y＝新しくできること・新しいページや欄・見た目が新しくなった・探せる範囲やアドレスが変わった・機能をやめた
  - Z＝直し・調整（不具合、崩れ、文言や表記、時間割データの訂正、小さな改善）
- 公開の場や口頭では、Z が 0 のとき「v2.7」と短く書いてかまいません。
- 1つの版は「運営者が OK を出して main に出した1日分」です。日付は main に入った日（日本時間）です。Y と Z が混ざったら、Y だけを1つ上げます。
- Instagram・ポスター・動画・手順書・テスト・自動化・運営用ダッシュボードの変更では、番号を上げません。
- 見た目も結果も変わらない変更は、同じ日の版か次の版の「裏側」に書きます。
- X（節目）は運営者が決めたときだけ上げます。3.0.0 は、テスト運用のあとの次の段階のために空けてあります。
- **v2.7.0 より前の番号は、2026-11-16 にあとからまとめて当てはめたものです。** 当時の画面や告知には出ていません。
  - v1.0.0 は「紹介ページを出した日」です。検索アプリを初めて人に見せた日ではありません。
  - 当てはめのときだけ、数日分を1つにまとめた版があります（v1.0.1・v1.0.2・v1.1.0・v1.8.0・v2.6.0）。見出しは最後の日で、期間は本文に書いています。
- 根拠のハッシュは main のものです。「番号の外:」と書いたハッシュは、番号の対象ではないファイルだけを変えたコミットです。
- この番号は、app.py の ASSET_VERSION（キャッシュを切り替えるための値）とは別のものです。
- 詳しい決まりは `docs/OPERATIONS.md` の「4.11 版番号の付け方」にあります。
