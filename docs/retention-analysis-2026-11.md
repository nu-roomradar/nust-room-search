# RoomRadar 定着の分析（GA4 2026-10-12〜11-08、28日）

ファイルの略記：R＝ga4_retention.json、B＝ga4_breakdown.json、W＝ga4_weekly.json（2026-11-09 に取った `data/` の同名ファイル）

## 1. 結論

- **初回の体験そのものは悪くありません。** アプリの新規684台のうち87%（597/684セッション）がエンゲージし、75%（511台）は自分でも検索しています（R.new_vs_returning、R.app_events_nvr）。
- **離れているのは「初回」と「次に教室が要る日」の間です。** 2回目のセッションがあった新規は多くて192台（28%。同じ日の開き直しも含む）で、少なくとも491台（72%）は1回しか開いていません。最大の流入は10/28の学生課メールで来た404台（新規の59%）ですが、翌週（day6〜8）に戻ったのは20・15・13台（3〜5%）でした（R.cohorts）。10/26週の新規が翌週も来た割合は約1割で、これも上限の値です。
- **中心の原因は、アプリ自身に「次に開く入口」が無いことです。** アイコンも manifest も無く、校舎は毎回「すべて」に戻ります。再訪のうち参照元が「直接」だったのは32セッション・11台だけでした（R.app_channels_nvr）。
- **数字を読むときの注意があります。** GA4 は米国太平洋時間で日付を切っています。また iOS Safari は計測用の cookie を7日で消します。このため D1 と D7 は日付がずれ、低めに出ます。**最初にタイムゾーンを直してください。**

## 2. 新しく来た人が離れる構造

流れ：**入口**（ポスターQR・学生課メール・Instagram）→ **LP** → **アプリの初回**（自動で「いまの空き」が出る）→ **次に教室が要る瞬間**（平日、日本時間9〜16時の授業の合間）→ **戻る**

1. **入口からアプリまで：漏れは小さいです。** LP の新規ブラウザのうち、アプリに新規として届かなかったのは10/28で22%、11/2〜5で9%でした（R.lp_daily_nvr・R.app_daily_nvr）。
2. **初回：エンゲージはしていますが、見せ方で損をしています。**
   - スマホ幅（390×844）だと、授業時間中は最初の画面に教室カードが1枚も入りません。最初のカードは760px台から始まります（Playwright で実測）。
   - 既定の「すべての校舎」で空きと出るのは平均125.1室です。そのうち81.0室は船橋で、テスト運用の対象になる普通教室は31.5室だけです（schedule_final.db で計算）。
   - タワー・スコラは名前の文字列順に並ぶので、7階以上が先頭に来ます（app.py:522）。
3. **初回から次の必要な瞬間まで：ここが最大の離脱点です。**
   - 検索は POST で、URL を開いたとき（GET）の校舎は常に「すべて」になります（app.py:438）。手動検索の52.6%（611/1161、B.search_building）は校舎を指定しているのに、開くたびに選び直しになります。
   - 開いたままのタブに戻ると、時計だけが進み、結果は前の時限のままです（static/app.js:8-23）。
   - 再訪セッションの91%（352/387）は参照元が LP と記録されています。ただし LP 側の再訪セッションは219しかありません。残っていたアプリのタブを開き直した分が多いとみられ、本当の入口は分かりません。
4. **戻ったあと：使い方は「開いて見て閉じる」です。** 再訪者は1回29.4秒、手動検索は1回あたり0.86回でした（R.new_vs_returning、R.app_events_nvr）。10/28組は翌週の同じ曜日のあたりに最も多く戻っていて、週単位で使う兆しがあります。ただし各日30台未満で、11/3と11/6の投稿とも重なっています。
5. **信頼：空振りが増えています。**
   - 「実は使われていた」の報告は、取り消しを除いて65件でした（B.events）。週ごとの報告÷利用者は7.0%から11.2%に上がっています（W）。
   - 報告は時限が終わると消え、データの修正にはつながりません（app.py:364）。
   - 時間割の原本は49ファイルすべて4/2版です。学期中の教室変更は2件しか入っておらず、読み取り誤りの教室名「701752」も残っています。

> **別枠：学生課の了承が要るもの・ルールに関わるもの（上の表には入れていない）**
> - **船橋を外す・タワー・スコラは6階まで**：正式なメールが来るまで触りません。催促は運営からできます。外すときは、覚えた校舎が船橋の人を「すべて」に戻して一行案内します。船橋の手動検索204件（17.6%）が消えるので、前後を比べるときは駿河台だけにします（「すべて」の検索にも船橋が入っています）。
> - **実験室・ホール・製図室を一覧から外す**：教室マスタの方針が変わるので、運営の判断と、学生課に部屋ごとの確認が要ります。
> - **画面に「先週この時限に報告あり」を出す**：テスト運用中の新しい公開機能になります。運営の承認と学生課への共有が要ります。GA4 から自動で拾う形にはしません（測定IDが公開されていて偽装できるため）。報告を「いまと直前の時限」だけに絞る案は、10/22の運営判断を変えることになります。
> - **次の一斉周知の時刻（平日12:30前後）と UTM 付きの URL**：お願いはできますが、決めるのは学生課です。根拠も弱いです（夜のメールでも1日で新規404台）。ポスターの文言を変えるときも学生課の確認が要ります。LP の1画面目の作り直しは保留のままです（11/06）。

## 5. 分からないこと・データの限界

- **タイムゾーンのずれ**：日付は太平洋時間で切れています。10/28組の D1（13台）は日本時間の木曜夕方〜金曜夕方にあたり、「翌日」の値ではありません。週の表からは日本時間の月曜6:07〜17時が抜けています。最終日の11/8も、まだ途中までしか入っていません。
- **iOS の cookie**：7日来ないと消えるので、それ以上あけて戻った人は「新規」に数え直されます。D7 以降は低めに出ます。ホーム画面アプリやアプリ内ブラウザも、Safari とは保存領域が別なので新規に数えられます。
- **ドメインが別**：LP とアプリは人単位でつなげません。LP のクリック計測には取りこぼしがあります（461 < 641）。
- **「再訪」の中身**：同じ日の開き直しが入っています（10/28だけで82台）。参照元 LP の352は、実際の入口を表していません。
- **数が小さい**：30未満の値（各日の戻り、Direct 11、(not set) 25、Instagram 経由の再訪8）は目安です。週単位で使う兆しは、投稿の影響と切り分けられていません。
- **確かめていないこと**：後期の更新版の時間割表があるか。PC の再訪比が低いのは、スマホに引き継げなかったからか（夜に自宅の PC で開いた人が多かっただけ、という説明もつく）。iOS 26 で manifest の display が効くか（iPad の実機で確認）。
- **裏付けが無かった主張**：「夜に来たから定着しない」は支持されませんでした（同じ日の開き直しは10/28組20.3%、昼に来た組21.1%）。「ポスターは Instagram が主役」は、2種類あってどこに貼ったかの記録がありません。「初回の4分の1が授業終了の画面」は、20:30以降の訪問が約8%しかありません。「木曜の検索41%は翌日の下見」は、20:30以降の既定がもともと木曜1限なので言えません。
