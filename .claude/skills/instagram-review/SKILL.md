# Instagram の振り返りと次の投稿（改善のサイクル）

サイクルは「**記録 → 分析 → 案 → 投稿 → 測る**」をくり返す。
- 記録は自動。毎週月曜 6:17 に Actions「Instagram 週次の記録」が動く。
- この手順は、分析と案の部分を受け持つ。
- 前回の案が当たったかを、次の回で必ず答え合わせする。

## 1. 材料をそろえる

**最新のデータを取り込む**
- データは bot が `main` に書く。作業ブランチにいるときは、まず次で取り込む。
  `git fetch origin main && git checkout FETCH_HEAD -- data/instagram_posts.json data/instagram_post_snapshots.json data/instagram_history.json data/instagram_posts.md`
- 急いで最新が欲しいときは、Actions「Instagram 週次の記録」（`instagram-insights.yml`）を workflow_dispatch で起動する。起動のときは運営者に確認が出る。

**ファイルと中身**
- `data/instagram_posts.json`：ストーリー以外の全投稿の「いま」の数字と、分析用の項目。
  - 数字：`views`（閲覧）、`reach`（見た人）、`likes`・`saved`・`shares`・`comments`、`total_interactions`
  - 率：`engagement_rate`（反応÷リーチ）、`save_share_rate`（保存＋シェア÷リーチ）
  - 投稿の情報：`kind`（画像／カルーセル／リール）、`slides`（枚数）、`headline`（キャプションの1行目）、`hashtags`、`caption_length`
  - 時刻：`posted_jst`・`weekday`・`hour`（日本時間）、`age_days`（取った日までの日数）
  - `notes` に取れなかった数字が書いてある。
- `data/instagram_post_snapshots.json`：取りに行くたびの投稿ごとの数字（`date`・`id`・`age_days`）。伸び方と、投稿から同じ日数どうしの比較に使う。
- `data/instagram_history.json`：アカウントの数字。日付ごとに、フォロワー数と直前7日のリーチ・閲覧などが入っている。
  - 2026-08 までの行は古い集計のもの。
  - 2026-11-18 からの行は、直前7日の合計で、名前の最後に `_7d` が付いている（`reach_7d` など。期間は `period`）。
- `data/instagram_posts.md`：人が読む表。運営者に見せるときの下敷き。
- 画像：`assets/instagram/`（ファイル名で投稿と対応をとる）。中身を見るときは Read で開く。
- 前回までの振り返り：`docs/instagram_review.md`。前回の「次に試すこと」を先に読む。
- アプリの利用：`data/ga4_weekly.md`。いまは「どの投稿から来たか」までは分からない。投稿した週と、アプリの訪問の増え方を並べて見る程度にとどめる。

## 2. 分析する

1. **数字が欠けていないか確かめる。** `notes` と取得日を見る。権限切れなどで `views`・`reach` が空なら、分析を止めて運営者に伝える（トークンの扱いは docs/OPERATIONS.md 4.5・4.12）。
2. **公平に比べる。**
   - **数字は累計。** 新しい投稿ほど小さく出る。比べるときは、snapshots から投稿後7日ごろの値を使う。無ければ `age_days` が7以上の投稿どうしで比べる。
   - **件数は数十件と少ない。** 平均より中央値で見る。1件の外れ値で結論を出さない。2件以下の傾向は「仮説」と書く。
   - **時期で条件が違う。** テスト運用（2026-10-13〜）、ポスター掲示（10/28〜）、フォロワー数は時期で違う。届いた広さは「リーチ÷その時のフォロワー数」でも見る。
3. **3つの面で見る。**
   - 届いたか：`reach`・`views`
   - 響いたか：`engagement_rate`・`save_share_rate`。保存とシェアは「役に立つ」「人に教えたい」のしるし。
   - 使ってもらえたか：GA4 の週ごとの訪問。弱い手がかりとして扱う。
4. **切り口を変えて比べる。**
   - 種類と枚数
   - 内容の型：使い方／新機能・アップデート／季節／お知らせ／データ紹介（例：「いつがねらい目？」）／運営の紹介。型は見出しと画像から自分で分ける。分けた表は結果に残す。
   - 見出しの書き方：疑問形、数字、絵文字、呼びかけ
   - 曜日と時刻
   - キャプションの長さ、ハッシュタグ
5. **結論の形。** 「傾向 → 根拠（どの投稿の、どの数字）→ 次に試すこと」の順に書く。

## 3. 次の投稿の案を作る

- 案は2〜3個。どの案にも次を書く。
  - ねらい：上げたい数字
  - 型と見出しの案
  - 画像の構成
  - 投稿する曜日・時刻
  - 比べる相手：結果を比べる過去の投稿
- 1回の投稿で変えるのは1つの要素だけにする。何が効いたか分かるようにするため。
- 投稿するときは `/instagram-post` の手順に従う。入力一式を運営者に見せて、承認を取ってから投稿する。

**守ること（CLAUDE.md のルールとあわせて）**
- キャプションには、`#日大生プロジェクト`（投稿の仕組みが自動で付ける）と「試験運用中・大学公式ではない」の文を入れる。
- 「予約」「確保」と書かない。
- 利用人数の目安は出さない。
- 船橋校舎は載せない。
- 他学部アンケートの結果は出さない。
- 顔の分かる人、実在の会社や大学のロゴ、既存の曲は使わない。
- 12/19 より後の運用は決まっていない。約束する書き方をしない。

## 4. 記録する

`docs/instagram_review.md` の先頭に、その回の振り返りを足す。
- 日付と、使ったデータの取得日
- 前回の「次に試すこと」の答え合わせ
- 分かった傾向（根拠つき）
- 次に試すこと

公開リポジトリなので、個人名、アンケートの結果、秘密の値は書かない。

## 5. 運営者に伝える

- 日本語で、結論から伝える。
- 数字は根拠として、必要な分だけにする。
- 決めてほしいことには、おすすめを添える。
- 表が要るときは `data/instagram_posts.md` から抜き出す。
